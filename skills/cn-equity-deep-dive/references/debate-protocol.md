# 多空辩论协议

这一步的目的不是「平衡地列出优缺点」——那是免责声明，不是研究。目的是**把多头逻辑打到只剩站得住的部分**。

---

## 一、做空者审计

**角色**：你是一家顶级做空基金的分析师，任务是证明前面的多头逻辑完全错误。

按 10 个攻击面逐一寻找弹药。每个面都要给出**你所能构造的最强论点**，不是"存在一定风险"这种废话。

| # | 攻击面 | 具体找什么 |
|---:|---|---|
| S1 | 利润质量 | CFO/净利长期背离、应收与存货增速超过收入、非经常性损益撑利润、政府补助依赖 |
| S2 | 收入真实性 | 客户集中度、关联销售、海外收入无法验证、渠道压货、Q4 收入异常 |
| S3 | 利益输送 | 关联采购溢价、对外担保、资金拆借、高溢价收购关联方资产、存贷双高 |
| S4 | 大股东行为 | 质押逼近平仓、持续减持、股权激励目标明显偏低（变相发福利） |
| S5 | 周期与过剩 | **当前是否 Peak Earnings**、行业新增产能、价格下行、库存周期见顶 |
| S6 | 竞争恶化 | 新进入者、价格战、份额流失、核心客户自研替代 |
| S7 | 政策逆风 | 集采、价格管制、补贴退坡、环保限产、出口管制、数据安全 |
| S8 | 技术替代 | 技术路线切换、商业模式过时、10 年后这门生意还在不在 |
| S9 | 估值过高 | Reverse DCF 显示隐含假设极度乐观、与同行比无理由的溢价 |
| S10 | 管理层诚信 | 承诺未兑现史、频繁变更募投、监管问询与处罚记录 |

### 硬性要求

- 每条论点**必须有数字支撑**，没有数字的猜想不写
- 某个攻击面确实不成立时，明确写「**S7 不构成有效空头论据：该公司不在集采范围内**」——不要为凑数硬写
- 全部扫完后，选出**最强的 1–3 条**作为核心空头逻辑，其余降级为背景

---

## 二、多头反驳

**角色**：长期主义基金经理。逐条回应上面的核心空头逻辑。

规则：

- 只能用**数据、事实、商业逻辑**回应
- 禁止「长期看好」「赛道优质」「管理层优秀」这类无信息量的辩护
- **反驳不了就承认**。明确写「该项空头论点成立，我们此前的判断有误」，然后说明它对估值的影响
- 每一条回应都要落到**对预测数字或概率权重的具体调整**上，而不是停留在定性

## 三、投委会裁决

以 Investment Committee 主席身份填这张表：

```markdown
| 维度 | 内容 |
|---|---|
| 多头最强论点 | <1 条，带数字> |
| 空头最强论点 | <1 条，带数字> |
| 已反映在价格里的风险 | <哪些利空已经被跌进去了，依据是当前估值隐含假设> |
| 尚未反映的风险 | <哪些市场还没定价，为什么> |

**裁决：** Buy / Watch / Avoid

**裁决理由：** <3–5 句，必须回应上面四行>
```

**判断「是否已反映在价格里」的方法**：回到 Reverse DCF。若当前价格隐含的增长率已经低于 Bear Case 假设，则大部分坏消息已定价；若隐含增长率仍高于 Base Case，则尚未定价。

## 四、Pre-Mortem

假设：**三年以后这笔投资亏损 50%。**

倒推最可能的原因，至少 5 个。每个原因必须填写：

```markdown
### 原因 N：<一句话>

- **发生了什么**：<具体情节，不是抽象风险>
- **概率**：<低 / 中 / 高>
- **现在是否已有早期迹象**：<有 / 无。有则列出具体迹象与数据>
- **领先指标**：<可观测、可跟踪的指标>
```

**「现在是否已有早期迹象」是整份报告信息密度最高的一栏**——它把风险从"未来可能发生"变成"现在可以观察"。空白一律写「暂无迹象」，不许留空或编造。

---

## 五、Kill Criteria 设计

从「空头最强论点」和「Pre-Mortem 的高概率原因」中，转化为 5–10 条**可量化、可观测**的失效标准。

**格式要求**：指标 + 阈值 + 频率。三者缺一不可。

好的写法：

> 连续 2 个季度收入同比增速 < 5%（当前 18%）
> 毛利率跌破 28%（当前 34%，近 3 年最低 30%）
> 经营活动现金流净额连续 2 个半年报为负
> 控股股东质押比例上升至 60% 以上
> 核心产品市占率连续 2 年下滑（当前 23%，来源：XX 研报）

坏的写法：

> 行业竞争加剧 ← 不可量化
> 管理层执行力下降 ← 不可观测
> 基本面恶化 ← 没有阈值

**触发任一条 Kill Criterion 时，不是"减仓观察"，而是投资逻辑已被证伪，必须重新从 Stage 1 做起。**

Kill Criteria 同时构成第六节「季度监控 Dashboard」的阈值来源。
