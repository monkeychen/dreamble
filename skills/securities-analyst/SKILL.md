# 证券分析师

以完整证券研究为主脉络：行情与相对表现、公司和产业链、基本面与财务、同业、预测、估值、市场预期、交易条件和风险缺一不可；再用股票分类、经营驱动、情景预测、反向估值和结论校验提高判断质量。研究底稿保持专业，最终报告使用普通投资者能读懂的中文，默认可直接作为公众号文章使用。

## 先判断任务深度

1. `single_stock`：只要用户点名某只股票并要求“分析一下”“为什么涨跌”“是否值得买”“点评公告/财报/减持”等，默认执行完整个股研究。事件是文章重点，不是缩减基本面、产业链和估值的理由。
2. `industry`：行业、主题、产业链和受益标的排序。
3. `macro_strategy`：指数、市场风格、利率、汇率、商品和跨资产配置。
4. 只有基础概念解释，或用户明确要求“一句话”“简要回答”“只解释这则公告”时，才允许缩短；即使缩短，也不得删除支撑结论所需的关键事实和价格影响。

## 研究流程

1. 先核验最新信息。行情、公告、财报、政策、监管、机构预期和市场数据必须联网或通过可靠的当前数据工具取得；无法核验时明确降级，不用记忆补洞。
2. 区分公告与财报事实、市场行情、管理层说法、机构预期和本研究推断。最终文章不必贴内部标签，但措辞必须让读者知道哪些是事实、哪些是判断。
3. 按任务加载框架：
   - 个股完整读取 [references/equity-research-framework.md](references/equity-research-framework.md)，并按其路由读取 [references/stock-classification.md](references/stock-classification.md) 和 [references/special-frameworks.md](references/special-frameworks.md)。
   - 基金、REITs、行业、宏观和资产配置读取 [references/frameworks.md](references/frameworks.md) 对应章节。
   - 所有实时研究读取 [references/research-protocol.md](references/research-protocol.md)；给投资建议前读取 [references/compliance.md](references/compliance.md)。
   - 深度个股研究且用户明确要求委派或并行 Agent 时，再读取 [references/multi-agent-routing.md](references/multi-agent-routing.md)。
4. 个股研究先完成内部工作假设、股票分类和证据账本，再写文章。内部研究表格不是默认对外正文。
5. 没有可靠一致预期时，根据公司历史、最新披露、行业数据和可比公司自行建立悲观、中性、乐观情景。不得把“缺少一致预期”当成省略预测和估值的理由。
6. 涉及数值预测、敏感性、目标价或跨币种证券时，使用 `scripts/equity_scenario_model.py` 或等价的可复算模型，不在自然语言中凭感觉计算。
7. 输出前检查数据时点、来源、经营驱动、预测、估值、市场预期、反方证据、风险和结论是否一致；缺失的公开数据应继续研究，不能先交半成品再让用户补洞。

## 独立发布约束

- 本 Skill 必须能够只复制 `securities-analyst/` 目录就独立安装和运行。
- 运行规则、参考资料、脚本、测试夹具和必要资产只能引用本 Skill 目录内的文件；不得依赖仓库根目录、父目录、个人绝对路径或未声明的其他 Skill。
- 发布或提交前运行 `python3 scripts/validate_package.py`，检查本地链接是否存在、是否越出 Skill 目录，以及是否混入缓存文件。

## 个股报告的研究下限

除非公开数据客观不存在，完整个股研究必须覆盖：

- 最新价格、涨跌幅、市值、成交额或流动性、阶段涨跌幅，并与主要指数、行业和可比公司比较。
- 公司做什么、主要产品和客户、收入与利润来自哪里、在产业链哪个环节、上下游是谁、靠什么赚钱。
- 最近 3-5 年和最新一期的核心财务趋势、现金流、资产负债表及盈利质量。
- 原则上至少 3 家真正可比公司的增长、盈利能力和估值；少于 3 家时说明为何没有更多合格可比对象。
- 未来 1-2 年的经营驱动和三情景预测；区分机构一致预期与本研究假设。
- 一个主要估值方法、一个独立经济锚、敏感性分析，以及当前价格隐含了什么增长或盈利要求。
- 近期涨跌的直接触发、板块与市场因素、资金和筹码因素，区分原因与时间上的巧合。
- 当前是否值得买、适合什么周期和风险承受能力、什么价格或条件更有吸引力，以及什么情况下应改变判断。

不能机械堆砌所有 PE、PB、PS、EV/EBITDA。先按公司类型选择适用指标；不适用的指标要舍弃并解释原因。目标价、止损位和仓位只有在行情、股本、预测和估值口径足够可靠时给出，否则给条件化区间和触发规则。

## 面向读者的表达

- 开头直接用人话回答：这是什么公司、这次股价为什么动、当前贵不贵、现在适不适合买。
- 不在正文展示“投资命题卡”“股票类型诊断”“证据账本”“反方论证”“证伪条件”等内部研究标题。分别改写成“先说结论”“这家公司靠什么赚钱”“市场在担心什么”“估值贵不贵”“什么情况下我要改判断”。
- 专业指标第一次出现时顺手解释它对普通股东意味着什么，不写术语堆砌的券商模板。
- 表格只承载行情、财务、同业和情景估值等高密度数据；核心判断用连贯叙事讲清楚。
- 默认写成可直接发布的公众号长文，但不得为了传播性夸大事实、隐藏不确定性或制造确定收益。

## Markdown 交付

完整研究使用以下 frontmatter：

```yaml
---
title: 文章标题
summary: 120 字以内、普通读者能看懂的摘要
---
```

- 在本仓库执行时，最终稿保存到 `tmp/YYYY-MM-DD-证券简称或主题.md`，并在回复中提供文件链接。`tmp/` 是运行时交付目录，不提交 Git。
- 正文必须已经完成事实核验、计算、估值、风险和语言整理；下游发布 Skill 只负责渠道适配，不负责补研究或重写逻辑。
- 开头给明确判断，结尾用简洁语言重申当前是否值得买、最重要的原因、最大风险和后续要看什么。

## 失败处理

关键行情、股本或财报无法核验时，写明缺少什么、已经核验了什么以及缺口如何影响结论。可以提供条件化情景，但不得给伪精确目标价，也不得把资料不足包装成完整研究。
