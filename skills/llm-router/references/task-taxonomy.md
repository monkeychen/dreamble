# 任务分类 → 推理等级

把用户的问题映射到统一推理等级 L0–L4。这张表解决的是"这个任务到底要不要让模型想"。

## 一、判定主轴

只问一个问题：**这个任务需不需要模型自己规划路径？**

- **照着做就行**（输入到输出是相对固定的映射）→ L0 / L1
- **得想清楚再动手**（有多条可能路径、需要权衡、错了要回退）→ L2 起

第二条轴是**上下文规模**，它决定模型档位，不决定推理等级。别把"文章很长"误判成"需要深度推理"——长文是上下文问题，不是推理问题。

## 二、任务族对照表

### L0 · 不推理

| 任务 | 说明 |
|---|---|
| 意图分类、打标签、路由分发 | 输出固定形状，frontier 模型也产不出更好的 30 个 token |
| 结构化抽取（JSON/表格字段） | 有 schema 约束时尤其不需要推理 |
| 格式转换（XML↔JSON、Markdown 清洗） | 机械映射 |
| 转录后处理、ASR 文本规整 | 注意：Gemini 这类必须显式 `minimal`，否则烧推理预算 |
| PII 脱敏、敏感词过滤 | 规则性任务 |
| 简单改写、纠错、大小写规整 | 无歧义转换 |

**判定信号**：能写出明确规则或 schema 的，基本都是 L0。

### L1 · 浅推理

| 任务 | 说明 |
|---|---|
| 摘要（单文档、无跨文档推理） | 压缩，不需要规划 |
| 翻译 | 除非文学翻译需要反复推敲 |
| 常规写作：邮件、通知、商品描述、社媒短文案 | 模板化程度高 |
| 简单问答、单跳知识检索 | 能从检索内容直接得出 |
| 模板化代码、单文件脚本、CRUD 样板 | 路径已知 |
| 单步工具选择 | 选一个工具，不需要多步规划 |

**判定信号**：一次就能做对，做错也是局部小错、容易改。

### L2 · 标准推理

| 任务 | 说明 |
|---|---|
| 多文件编码、跨模块重构 | 需要理解依赖关系 |
| 文档综合（多文档 → 一份结论） | 需要交叉比对 |
| 数据分析、表格处理、写 SQL 并校验 | 需要验证中间结果 |
| RAG 问答（需要综合多段检索结果） | 不是单跳 |
| Agent 常规步骤、多步工具循环 | 每步依赖上一步结果 |
| 长文生成（报告、课程稿、技术文档） | **要点：这是上下文 + 连贯性问题，不是推理深度问题** |
| 常规代码审查 | 找明显问题 |

**判定信号**：需要"先看 A 再决定 B"，但路径基本可预期。这是**多数生产任务的落点**。

### L3 · 深度推理

| 任务 | 说明 |
|---|---|
| 复杂调试、根因分析 | 需要假设—验证循环 |
| 架构决策、技术选型、方案权衡 | 没有标准答案，需要论证 |
| 深度代码审查、安全评审 | 漏掉的代价高 |
| 多步 agent 长链路（>10 步） | 误差会累积 |
| 数学推导、算法设计 | 需要严谨链 |
| 合同/合规文本审查 | 错误代价高，建议叠加 `mode: pro` |

**判定信号**：错了要返工，或者需要说服别人（有论证责任）。

### L4 · 极限推理

| 任务 | 说明 |
|---|---|
| 竞赛数学、形式化证明 | 长链条严谨推理 |
| 研究级难题、开放性科学问题 | 无先例可循 |
| 长周期自主 agent（无人值守跑几十分钟以上） | 需要持续自我纠错 |
| 高风险最终复核（安全、资金、对外发布前） | 兜底审查 |

**判定信号**：你自己也要花一小时以上想的，才配 L4。**L4 稀缺且昂贵，别滥用。**

## 三、关键词启发式

用户输入简短时，用这些词快速定位（有冲突时取较高等级，再看上下文规模校准）：

| 出现这些词 | 倾向 |
|---|---|
| 分类、抽取、提取、打标、路由、转换、清洗、规整、批量 | L0 |
| 摘要、总结、翻译、改写、润色、写一封、写个通知、生成描述 | L1 |
| 重构、跨文件、分析这份数据、综合这几份、多步、agent、写个报告、做个方案 | L2 |
| 调试、排查、为什么报错、根因、架构、选型、权衡、评审、审查、优化性能 | L3 |
| 证明、推导、最难、无人值守、兜底、最终复核、研究级 | L4 |

## 四、四档校准器

定完基础等级后，用这四个因子上下微调 ±1 档：

**错误代价**
- low（重写即可）→ 降 1 档
- high（资金/安全/对外发布）→ 升 1 档，并考虑 `mode: pro`

**时延要求**
- realtime（交互、语音）→ 封顶 L2，L3/L4 的延迟用户受不了
- batch（离线可等）→ 不限制，且开 batch 服务档（普遍 5 折）

**上下文规模**
- small/medium → 不影响等级
- large（>200K）→ **升模型档位，不是升 effort**。长上下文需求用高 effort 补不回来

**是否可验证**
- 输出能用程序校验（有 schema、有单测、有 golden answer）→ 降 1 档，靠重试兜底更划算
- 输出只能人来判断 → 维持或升 1 档

## 五、常见误判

**"帮我写一篇长文章" → 不是 L3。**
长文生成是上下文 + 连贯性问题。真正的解法是选中高档模型（上下文稳）+ `verbosity: high`，而不是把 effort 拉满。effort 拉满只会让它在开头纠结更久，不会让后半段更连贯。

**"这个 bug 找不到原因" → 至少 L3，可能 L4。**
需要假设—验证循环，是典型的深度推理任务。但前提是给它足够的上下文——先把相关代码和测试输出喂进去，再谈 effort。

**"批量处理 10 万条数据" → 先想能不能降到 L0。**
这类任务的瓶颈是成本不是质量。正确做法：先用 L0 跑，抽样验证，失败的再升级。这叫 cascade，比全程用 L2 便宜一个数量级。

**"这个方案帮我评估一下" → L3，且考虑 `mode: pro`。**
有论证责任的任务，答错代价高于 token 成本。

**需不需要联网 ≠ 需不需要深度推理。**
检索是工具能力，不是推理能力。需要实时信息的任务该配搜索工具，不是把 effort 拉高。

## 六、Cascade 路由模式

对有量级差异的任务流，别用单一模型从头跑到尾。三级路由：

```
第 1 级（80% 流量）：便宜模型 + 低 effort
   ↓ 输出校验失败 / 置信度低 / 任务被标记为复杂
第 2 级（15%）：中档模型 + 中 effort
   ↓ 仍然失败 / 高风险任务
第 3 级（5%）：旗舰模型 + 高 effort（必要时 + pro mode）
```

例：80% 请求交给 GPT-5.6 Luna 或 DeepSeek V4-Flash，15% 升级到 Terra / Sonnet 5，5% 上 Sol / Opus。混合成本能压到接近第 1 级的单价，而质量接近第 3 级。

**前提**：第 1 级必须有可靠的失败判定（schema 校验、单测、自检提示），否则 cascade 只是把成本转移到了重试上。
