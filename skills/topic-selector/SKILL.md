# 「聊哉梦呓」公众号选题系统

## 账号定位（选题的一切判断都基于此）

- **账号名**：聊哉梦呓
- **账号气质**：时光易逝留不住，但思绪偶尔可以在这里停留
- **核心定位（不变量）**：**一个人用 AI 把想法做成能跑的东西，并把全过程和坑摊开给人看。**

  话题可以跨域——AI 工程、开源产品、运维事故、投资判断、内容生产流水线都行。
  但每篇都必须在证明同一件事：**这人是真做出来的，不是只有观点。**

- **主定位**：①「动手做的人」（builder）。**辅定位**：②「用框架判断的人」——只写可复用的判断框架，不写个股。
- **目标读者**：会用或想学会用 AI 做工具的开发者与 power user；想用 AI 把自己重复劳动自动化的人；对"一个人能不能干完一整套系统"感兴趣的人。
- **竞争差异**：绝大多数写 AI 的人只有观点和截图，没有能下载的产物。我们有 wx-kit、xtract 这类真开源、真跑起来、真有人用的东西，且愿意写"为什么砍掉某个功能"这类不光彩的决策。

### 定位单位是「不变量」，不是「领域」

**跨域没问题，纯热点驱动有问题。** 选题标准不是"今天什么热"，而是"这件事我能不能给出只有我能给的一层"。

热点是**入口**，不是定位。定位的作用是给热点装一个**过滤器**：

| 面对同一个热点 | ❌ 纯热点驱动 | ✅ 本号的写法 |
|---|---|---|
| 某 AI 工具发布 | 「XX 来了！十大新功能盘点」 | 「我拿它替换了自己流水线里的一环，省了多少事、哪里不如原来」 |
| 某平台改协议/封接口 | 「XX 突然不能用了」 | 「我为此砍掉了产品的一个核心功能，这是决策过程」 |
| 某次市场大跌 | 「今天为什么跌」 | 「我的选股漏斗在这轮回撤里的表现，以及它设计时漏了什么」 |

判定口诀：**这篇文里的"我"能不能被换成任何一个同行？能换，就别写。**

## 五条内容线

选题必须归属到以下之一（或其交叉地带）。**①为主，②为辅；每周 1 篇的产能下，①占约 4/5。**

### 线1：造物记（主，约30%）

开源产品的设计决策与踩坑。落脚点是"为什么这么选、代价是什么"，不是功能罗列。

信号词：为什么砍掉、设计边界、权衡、重构、这个功能没做、踩了个坑

典型方向：
- wx-kit 为什么砍掉"按公众号批量下载历史文章"（微信侧列表接口封禁实测）
- xtract 为什么用真实浏览器在协议层拦截，而不是逆向官方接口
- stockfunnel 三步漏斗为什么这么分层，回测暴露了什么问题
- 一个功能的三种实现方案，我为什么选了最笨的那种

### 线2：拆机间（主，约25%）

读源码、拆机制，把黑盒讲明白。这类是历史表现最好的方向。

信号词：读源码、机制、原理、它是怎么、为什么行为不一致、逆向

典型方向：
- AI 工具的 skill 加载机制（扫描顺序、去重规则、路径解析不对称）
- 平台协议的隐性限制（公众号 API 错误码、频控、审查层）
- 某开源库的设计取舍，以及它在什么情况下会失效
- 本地跑大模型的真实瓶颈在哪（内存带宽、量化损失、上下文）

### 线3：流水线（主，约20%）

把重复劳动 AI 化/自动化的完整链路。对应"任何重复 3 遍的事就该自动化"这条工作哲学。

信号词：自动化、工作流、闭环、一键、脚本、串起来、少一步

典型方向：
- 从选题到双渠道发布的全自动链路是怎么搭的
- 几十个 skill 的治理：description 的 token 成本、加载冲突、版本漂移
- 用 AI 从上百篇文章提炼一个人格 skill 的过程
- 内容生产的数据复盘怎么回流成下一批选题

### 线4：事故现场（主，约15%）

真实故障的完整归因。最有共鸣、最难被抄袭的一类。

信号词：挂了、被封、报错、排查、误判、根因、折腾了两天

典型方向：
- 服务器 IP 被云平台封禁，从 CVE 误判到真凶定位的全过程
- fail2ban 把自己的诊断行为当成爆破封了
- sshd 配置"首值优先"导致的加固失效
- 某个依赖静默失效，表现为一个毫不相关的错误

### 线5：框架与判断（辅，约10%）

可复用的判断框架、周期认知、行为偏差。**严格不含个股、不含点位、不含买卖建议。**

信号词：怎么判断、框架、周期、认知偏差、概率、这事的本质

典型方向：
- 判断一个行业值不值得投入的分析框架（产能、含中量、成本结构）
- 散户行为偏差如何影响自己的工程决策（沉没成本、锚定）
- 用第一性原理拆解一个被广泛接受但并不准确的判断
- 工具选型的决策方法：什么时候自己造，什么时候用现成的

> ⚠️ **个股深度研究、含评级/目标价/买卖区间的内容一律不进公众号**（见选题红线）。
> 这类内容走 simiam.com 独立发表，用 `cn-equity-deep-dive` / `securities-analyst` skill 生产。

## 双渠道分工（硬规则）

公众号与 simiam.com 并行，但内容不是简单复制：

| 内容类型 | 公众号 | simiam.com |
|---|---|---|
| AI 工具实操、工程判断、踩坑复盘 | ✅ 首发 | ✅ 同步 |
| 开源项目更新（wx-kit / xtract） | ✅ 首发 | ✅ 同步 |
| 投资判断框架（无个股、无点位） | ✅ 可发 | ✅ 同步 |
| **个股深度研究、含评级/目标价/买卖区间** | ❌ **禁发** | ✅ 独发 |
| 服务器运维、事故排查 | ✅ | ✅ |
| 企业项目相关（脱敏后，只写方法论） | ✅ | ✅ |
| 超长技术文档（>5000字）、代码为主的内容 | ⚠️ 发短版或只发要点 | ✅ 全文 |

**为什么个股内容禁发**：微信公众平台对含明确荐股内容（点名股票代码+买卖评级、目标价/情景估值/具体价位、"建仓观察区"等主观策略语言）返回 **errcode 45166 invalid content hint** 拒稿。这是平台级硬墙，**弱化关键词也绕不过**——2026-09 已实测：第一层敏感词全部替换后仍 45166。不要浪费一轮尝试。

**脱敏规则**（企业项目相关选题）：可以写方法论、踩坑类型、架构选型的思考过程；**不写**业务数据、架构图、内部系统名称、客户名单、未公开的产品规划。

## 选题工作流

### 场景A：用户说"帮我想选题"或"没灵感了"

1. 先问一句边界：偏好哪条内容线，或近期手上有什么在做的东西（**在做的东西优先——真项目才有独家细节**）。
2. 检索近期相关动态：AI 工具发布、平台规则变化、自己项目的 issue/release、读过的源码。
3. 生成 5-8 个选题，每个包含：
   - **选题标题**（草拟，后续可调）
   - **所属内容线**
   - **一句话核心观点**（读完记住的那句话）
   - **独家性来源**（这篇为什么只有我能写——哪段代码、哪次事故、哪个决策）
   - **切入角度**（怎么开头，用什么钩子）
   - **选题评分**（用下面的评估体系）
   - **渠道**（公众号 / 仅站点 / 双发）
4. 给出推荐排序和理由。

### 场景B：用户给出一个具体话题/新闻/事件

1. 过一遍**热点过滤器**：这件事我能不能给出只有我能给的一层？（不能 → 直说，别硬凑）
2. 过一遍**选题红线**，特别是渠道判定（含个股 → 只能走站点）。
3. 如果适合，给 2-3 个不同切入角度，说清各自优劣。
4. 如果不适合，坦率说明原因，并给替代选题。

### 场景C：选题规划（周/月计划）

1. **默认产能：每周 1 篇，每篇 3 小时内。宁可不发，也不水一篇。**
2. 内容线比例参考：造物记 30% / 拆机间 25% / 流水线 20% / 事故现场 15% / 框架与判断 10%。允许按当期在做什么浮动，但**框架与判断不要连续两周以上占位**（会拉回旧定位）。
3. 节奏：深度长文与轻量短文交替。事故现场类适合穿插在连续的硬核技术文之间，缓解疲劳。
4. 为每个选题标注优先级和渠道。
5. 规划产出后写入选题库，带筛选记录（见 references/topic-library.md 的格式）。

## 选题评估体系

五个维度打分（每项 1-5 分），**总分 25**：

### 1. 独家性（这篇只有我能写吗？）— 权重最高
- 5分：基于自己写过的代码、真实事故、亲手做的决策，全网无同类
- 4分：有一手细节，别人只能从外部推测
- 3分：角度新，但素材公开可得
- 2分：大量同质化内容已存在
- 1分：纯信息搬运

### 2. 读者可用性（读者能拿走什么？）
- 5分：可直接复用的方法、脚本、判断清单
- 4分：能避开的坑或能少走的路
- 3分：认知增量，但需要自己转化
- 2分：需要较多铺垫才建立关联
- 1分：与读者无关

### 3. 内容深度（撑得起一篇吗？）
- 5分：有源码级/数据级证据链，能挖到根因
- 4分：素材充足，能支撑独立结论
- 3分：中等深度，有观点
- 2分：浅层讨论，难以超越常识
- 1分：话题太窄，一段话说完了

### 4. 传播潜力（会不会转发？）
- 5分：强共鸣（"我也踩过"）+ 强社交货币（"长见识了"）
- 4分：有明确转发动机
- 3分：有阅读价值但转发动机一般
- 2分：小众话题，传播受限
- 1分：几乎不会被分享

### 5. 调性契合度（像"聊哉梦呓"吗？）
- 5分：松弛、真诚、有明确判断、不端着，读完有余味
- 4分：高度契合，稍作调整即可
- 3分：基本契合，需要在角度上做文章
- 2分：有些勉强，可能变成说明书或营销文
- 1分：明显不符合定位

**判读**：
- 20-25：优质，强烈推荐
- 15-19：合格，值得写
- 10-14：一般，建议调整角度后重评
- <10：放弃
- **单项否决**：独家性 ≤2 分直接放弃，不看总分（这是本号的命根子）

## 选题红线（直接否决）

**平台合规类**
- ❌ 点名个股 + 买卖评级 / 目标价 / 情景估值 / 具体价位 / "建仓观察区"等主观策略语言 → **公众号必返 45166**，只能走站点
- ❌ 预测具体点位或涨跌方向
- ❌ 未公开的架构细节、业务数据、客户名称、内部系统名（企业项目相关）
- ❌ 涉及敏感政治话题或可能触发审核的内容

**内容质量类**
- ❌ 纯热点搬运（没有只有我能给的一层）
- ❌ 功能罗列式软文（"XX 的十大功能"）
- ❌ 标题党（内容撑不起标题承诺）
- ❌ 贩卖焦虑、制造恐慌（"再不学就被淘汰了"）
- ❌ 纯鸡汤（没有逻辑和事实支撑的感悟）
- ❌ 编造的经历、数据、用户反馈、效果数字

**运营类**
- ❌ 为填满排期而生成的重复内容
- ❌ 时效性过短（发出来就过时）

## 选题输出格式

```
📌 选题：[标题草案]
📂 内容线：[造物记 / 拆机间 / 流水线 / 事故现场 / 框架与判断]
💡 核心观点：[一句话]
🔑 独家性来源：[哪段代码 / 哪次事故 / 哪个决策]
🪝 切入钩子：[开头用什么吸引读者]
📊 评分：独家X + 可用X + 深度X + 传播X + 调性X = 总分XX/25
📮 渠道：[公众号首发+站点同步 / 仅站点 / 公众号短版+站点全文]
📝 推荐理由：[为什么值得写，潜在风险是什么]
```

## 选题灵感来源

主动找选题时，按**独家性从高到低**的顺序检索：

1. **自己手上的活**：正在做的项目、这周解决的 bug、刚读过的源码、刚踩的坑 ← **最优先，独家性最高**
2. **项目动态**：wx-kit / xtract 的 issue、用户反馈、release 变更
3. **工具生态变化**：AI 工具版本更新、平台规则调整、开源库弃坑或暴毙
4. **技能库治理记录**：skill 冲突、token 成本、加载机制异常（`.workbuddy/memory/` 里有大量一手素材）
5. **读者反馈**：评论区高频问题、后台留言
6. **市场与行业**：只作为②线（框架与判断）的触发器，不作为主线
7. **书籍/文章**：读到的某个方法论，结合自己的实践验证或反驳

> ⚠️ **不要从"今日热点榜"开始找选题。** 那是纯热点驱动的入口，独家性天然为 1-2 分。

## 额外提示

- 用户给的话题属于热点事件时，先用搜索工具获取事实，再判断能不能给出独家一层。**不要凭训练语料猜。**
- 选题可以成组：一个项目的一次大改，能拆出"设计决策"（造物记）+ "踩坑归因"（事故现场）+ "自动化链路"（流水线）三篇，形成矩阵。
- 鼓励跨线：最好的选题常在交叉地带，比如"用 AI 从 269 篇文章提炼一个人格 skill"同时覆盖流水线和拆机间。
- **每次选题规划后，把筛掉的选题和筛掉理由记进 topic-library.md 的选题库表**，让第 30 篇比第 1 篇更懂读者。
