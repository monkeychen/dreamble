# 「聊哉梦呓」常备选题库

> 选题灵感储备库。当用户缺乏灵感或需要非热点驱动的选题时，从中挑选并结合当下语境改造。
> 这些不是标题，是"选题种子"——需要根据具体时机和角度进一步发芽。
>
> **本库的选题必须满足：只有我能写。** 每类开头标注了独家性来源。

---

## 一、造物记（开源产品的设计决策与踩坑）

> 独家性来源：wx-kit / xtract / stockfunnel / x-reader 的真实代码与决策记录

### wx-kit 系列
- 为什么砍掉"按公众号批量下载历史文章"：微信侧列表接口封禁的跨平台实测
- 一个下载器的多格式导出该怎么设计：Markdown / PDF / JSON 各自的坑
- 图床挂了文章就裂：图片本地化的策略与失败案例
- 订阅只在电脑开着时运行：为什么不做 7×24 后台服务器
- 登录态过期时怎么"不装死"：错误提示的设计
- 从 Electron 到 brew/npm/DMG 三渠道分发的实际工作量

### xtract 系列
- 逆向库暴毙的时代：为什么改用真实浏览器在协议层拦截
- 抓取的库被官方改一次前端就死一次，这个循环怎么破
- 抓取与总结解耦：为什么改一句 Prompt 不该重爬一遍
- 高信噪比过滤：点赞门槛为什么比关键词过滤有效
- 7 个大模型统一调度，认证双轨（API-Key / 账号订阅免 Key）的取舍

### stockfunnel 系列
- A股三步漏斗：初筛、结构精筛、筹码定筛为什么这么分层
- 回测暴露的设计缺陷：漏斗在什么行情下会集体失效
- 个股历史 PE/PB 分位没有现成接口，只能自己算的全过程
- 一个选股工具最该做的不是选股，是告诉你"为什么不该买"

### 通用造物话题
- 功能做出来又砍掉：沉没成本在产品决策里怎么作祟
- 一个人做开源项目，最容易死在哪三件事上
- 开源不等于免费劳动：issue、PR、文档的时间账
- 为什么我不给开源项目做付费版（至少现在不做）

## 二、拆机间（读源码、拆机制）

> 独家性来源：亲手读过的源码与实测数据。历史表现最好的方向

### AI 工具机制
- WorkBuddy skill 扫描机制：五个加载源、去重顺序、路径解析的不对称
- skill description 的隐性成本：每轮请求都在付的 token（实测数据）
- 为什么改了 skill 不生效：会话启动快照机制
- `.gitignore` 匹配不到 symlink：一个反直觉的规则细节
- 软链、别名目录与加载源：`.codebuddy` / `.claude` / `.workbuddy` 的真实关系
- Claude Code 账号没了之后：多 provider 迁移的实测差异

### 平台协议与限制
- 公众号 API errcode 45166：内容审查的两层结构与实测边界
- 微信公众号 IP 白名单：为什么本机直连必失败，SSH 隧道怎么绕
- 企微群发频控、公众号频控：平台级限流的设计逻辑
- 「用其他应用打开」这个入口的技术前提是什么

### 本地推理与工程
- Mac Studio 本地跑 Qwen3 的真实瓶颈：内存带宽、量化、上下文长度
- 本地模型和 API 模型的成本分界线在哪

## 四、事故现场（真实故障的完整归因）

> 独家性来源：真实发生的事故 + 完整排查记录。**最有共鸣、最难被抄袭**

- 服务器 IP 被云平台封禁：从 CVE 误判到真凶定位的全过程
- 我的纯静态站被判定为 React RSC 漏洞源：一次错误归因的完整复盘
- fail2ban 把自己的诊断行为当成爆破封了
- sshd 配置是"首值优先"：一次加固静默失效
- 115,858 次密码爆破：一台公网服务器的真实日常
- 沙箱里的 `rm` 是假象：Git 操作陷入"删了又没删"的循环
- `index.lock` 每隔几十秒被重建：一个找不到凶手的排查过程
- 软链目录里 `git init`，结果在别人的仓库里创建了嵌套 `.git`
- Astro 内联脚本被打包成外链，导致首屏跳出漏采
- 某个依赖静默失效，表现为一个毫不相关的错误（通用母题，可写具体案例）

## 五、框架与判断（辅线，无个股）

> 独家性来源：跨领域实践形成的判断方法。**严禁个股、点位、买卖建议**

### 判断方法
- 判断一个行业值不值得投入：产能、含中量、成本结构三个维度
- 什么时候自己造，什么时候用现成的：工具选型的决策框架
- 第一性原理在工程决策里怎么用（而不是当口号喊）
- 一个功能的价值，等于它替代掉的重复次数 × 单次时间

### 认知偏差（跨界应用）
- 沉没成本如何影响产品决策：我为什么砍掉已经写好的功能
- 锚定效应在技术选型里的作用：第一个看到的方案凭什么赢
- 后视镜偏差：为什么复盘容易，预判难
- 「这次不一样」：工程里最危险的五个字

### 周期与结构
- 技术周期的位置判断：早期、中段、末端的信号差异
- 表面叙事 vs 实际逻辑：任何事件都要拆开两层看
- 算账思维：谁出钱、谁获益、谁承担代价

### 复盘判读（跟自己历史中位数比，不跟别人比）

| 现象 | 说明 | 下一步 |
|---|---|---|
| 阅读高、关注低 | 内容有吸引力，但关注理由不清楚 | 检查文末引导与账号定位表达 |

## 使用建议

1. **优先从「自己手上的活」找选题**，不要照搬本库标题。本库是种子，需要结合当下正在做的事重新发芽。
2. 优先选跨线融合选题——辨识度和深度通常都更好。
3. 常备选题是"内容蓄水池"，热点空窗期拿出来写，不用靠热点驱动。
4. 一个种子可以裂变：同一次事故能写"归因过程"（事故现场）和"设计教训"（造物记）两篇。
5. **事故现场类最容易爆也最难攒**——发生了就立刻记进本库，细节过一周就忘了。
